# 2026-10-23 DDR2 패턴 재생 수정 및 실제 FPGA 업로드 기록

## 변경 내용

- 실제 XST 소스 목록과 top-level 포트 불일치를 해결하고 세 `.prj` 및 `.xise`를 맞췄습니다. 실제 대상 패키지는 `ff1153`입니다.
- `USB_IO.vhd`: DDR 업로드 데이터의 행/패킷 경계 누락을 없애고, 연속 레지스터 쓰기 전달과 FIFO overflow 표시를 수정했습니다.
- `MEM_IO_Verilog.v` / `ddr_pattern_engine.v`: 선택한 패턴 ID를 메모리 주소에 전달합니다. 프레임당 6,144개의 128-bit word, 3,072개의 BL4 명령을 정확히 처리하고 FIFO/MIG stall을 처리합니다. 기존 `{pattern_id, offset, 2'b00}` 주소 배치와 MIG/IP는 그대로입니다.
- `dmd_frame_streamer.v`: 두 행 버퍼로 한 행의 8개 word를 연속 출력하고, Global MCP 이후 안정 시간을 확보합니다.
- `memory_playback.v`: 임의 ID 목록, 유한/무한 반복, 단일 패턴, 직접 ID 선택, USB 시작, GPIOA[0] 상승 에지 시작, 정지·상태 조회를 통합했습니다. 재생 중 설정 변경과 잘못된 ID/모드는 거부합니다. busy 중 트리거는 누적 대기하지 않고 무시 여부를 기록합니다.
- 연속 테이블 쓰기 직후 시작, 재업로드 직후 stale 상태, busy 중 직접 선택 요청 등의 경계 조건을 수정했습니다. BRAM 쓰기·타이밍 비교·시퀀스 전환 경로를 파이프라인화해 200MHz 타이밍을 맞췄습니다.
- 클럭 전체를 잘라내던 제약을 정리하고 CDC 첫 단계/안정적으로 유지되는 요청 데이터에 한정해 제약을 적용했습니다. 누락된 EXP1 테스트 출력 3개 핀을 복원했습니다.
- 추가 Python 패키지 없이 실행하는 ISE 빌드/ISim 회귀 검사, TI DLL 기반 패턴 전송 도구, 5개 테스트 패턴 생성기를 추가했습니다. 실행 없이 PASS를 출력하던 이전 테스트 스크립트를 교체했습니다.

기존 TI IO/PLL/TPG/DMD_control, 생성된 IP 및 `MEM_IO.vhd`는 변경하지 않았습니다. 초기에는 TI 경로가 선택됩니다. 이 보고서의 기능 비교 대상은 수정 전 RTL과 TI 경로이며, 기존 각 `.bit`의 모든 내부 기능을 역분석했다는 뜻은 아닙니다.

## 현재 기능과 시간의 의미

검증 범위는 **1024×768, 1-bit, 전체 프레임 Global update**입니다. 새 메모리 경로에서 Load2 및 Float/Single/Dual/Quad/Phased 재생은 지원하지 않습니다. ABI는 **D201**, 확장 주소는 **0x29–0x3E**입니다. [레지스터 명세](REGISTER_MAP.md)를 기준으로 사용합니다.

`repeat_count=1`은 목록 한 번, `N`은 목록 N번, `0`은 무한 반복입니다. `Arm`과 `repeat_count=1`을 사용하면 TTL 한 번에 5개 목록을 재생한 뒤 다음 트리거를 기다릴 수 있습니다.

`period_us`는 패턴의 MCP부터 다음 MCP까지의 최소 요청 간격입니다. 20µs가 허용 하한이며 실제 전송·안정 시간이 더 길면 간격도 늘어납니다. 역압력을 넣은 테스트에서 짧은 요청은 약 **64.5–65.9µs**, 100µs 요청은 **100.015µs**였습니다. 이 숫자는 특정 시뮬레이션 결과이고 실제 DMD의 측정 속도가 아닙니다. 전체 프레임 전송과 미러 안정 시간은 [TI DLPC410 데이터시트](https://www.ti.com/lit/gpn/DLPC410)를 따릅니다.

## JTAG 연결 및 업로드

처음에는 VM USB 2.0이 꺼져 있었고 케이블 연결 요청도 걸려 있었습니다. EHCI 활성화 → VM 정상 재시작 → 사용자가 PC 쪽 케이블 재연결 순서로 해결했습니다. 추가 소프트웨어 설치는 없었습니다. VirtualBox 7.2의 EHCI는 기본 구성입니다([Oracle 릴리스 노트](https://docs.oracle.com/en/virtualization/virtualbox/7.0/relnotes/ChangeLog.html)).

저장한 CDF에서 **iMPACT 위치 1=LX50, 위치 2=LX30**을 확인한 뒤 위치 1만 기록했습니다. 검색 로그의 발견 순서로 위치를 추정하지 않습니다. LX30 및 PROM/flash에는 기록하지 않았습니다. 이번 SRAM 구성은 전원을 끄면 유지되지 않습니다.

## 다음 단계: BMP·메모리·시퀀스 테스트

별도 [DMD-FPGA-Test](https://github.com/jin083/DMD-FPGA-Test) 저장소는 현재 [dlpc410](https://github.com/jin083/dlpc410/tree/feature/ddr2-memory-api)의 `dmd_ctrl.memory` 패키지를 기반으로 합니다. 초기에는 이 `hs_dmd` 저장소에 잘못 배치했으며 아래 위치 변경 사항을 적용했습니다. 당장 구현할 범위는 DLP7000 1024×768 숫자 1~10 BMP 생성, DDR2 저장, 개별 이미지 표시, 지정 순서·주기·횟수 재생, TTL 시작 및 정지입니다. 포토다이오드/ADC/오실로스코프 측정은 후속 계획으로 분리합니다.

실기 검증은 D4100/FX2 USB 연결·ABI 확인 → 검정/흰색 단일 패턴 저장·표시 → 5개 유한 반복 → TTL 시작 → 무한 반복/정지 순서로 진행합니다. 포토다이오드 전압과 가능하면 동일 수집 장비의 기준 트리거 채널을 함께 기록합니다. 샘플 시간축은 수집 장비에서 받아야 하며, PC 명령 전송 시각으로 µs 전환 시간을 판정하지 않습니다. 교정 전 전압을 광파워나 광자 수로 변환하지 않습니다.

후속 요청에 따라 `feature/dlpc410-python-api`에서 [Python 제어 API](DLPC410_PYTHON_API.md)를 구현했습니다. 테스트 저장소의 `feature/dlp7000-memory-tests`는 이 패키지로 숫자 BMP 1~10 생성·메모리 업로드·개별 표시·시퀀스 제어를 실행합니다. Detector 측정은 이후 계획으로 이동했습니다. 사용자가 전원을 내린 상태임을 알려주었으므로 이번 API/CLI는 장비 접근 없이 오프라인 테스트만 수행했습니다. FPGA 빌드 입력과 bitstream은 변경하지 않았습니다.

## Python 패키지 위치 및 설치 체계 수정

사용자가 지정한 실제 Python 제어 저장소는 `C:\Users\wlsgu\project\2026\DMD\dlpc410`입니다. D201 API와 Python 테스트를 그 저장소의 `feature/ddr2-memory-api` 브랜치로 이동했습니다. 기존 TI 제어 클래스와 DLL은 보존했습니다. `hs_dmd`의 Python 패키지 정의는 제거하고 독립 PowerShell 진단 도구는 유지합니다.
