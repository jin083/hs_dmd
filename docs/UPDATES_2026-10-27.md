- iMPACT: `Programmed successfully`, DONE=1, configured=1, startup 완료=1, CRC/ID/readback CRC 오류=0.
- [결과 JSON](../artifacts/dmd-program-20261027/programming_result.json), [체인 확인 로그](../artifacts/dmd-program-20261027/identify.log), [기록 로그](../artifacts/dmd-program-20261027/program.log), [실행 명령](../artifacts/dmd-program-20261027/program.cmd).

호스트 원본·복사본과 게스트 파일의 SHA-256을 확인했습니다. Python 도구의 `require_lx50_chain` 및 `verify_program_log`에도 이 성공 로그를 넣어 판정 통과를 확인했습니다. 이번 작업에서 RTL이나 bitstream을 새로 빌드하지 않았습니다.

## 직접 실행과 Python 도구

두 방식 모두 기존 ISE VM에서 ISE 14.7의 iMPACT를 실행합니다. `Identify`로 체인을 읽고, `assignFile -p 1`로 파일을 선택한 뒤 `Program -p 1`, `ReadStatusRegister -p 1`을 실행합니다. Python 도구는 이 절차에 파일 대상·해시 검사, 케이블 연결 처리, 로그 검사와 결과 저장을 추가합니다. 임시 파일 이름과 CDF 저장 명령의 차이는 FPGA에 기록하는 데이터의 차이가 아닙니다.

직접 명령 성공 후 다음 Python 명령을 실행하여 종료 코드 0과 DONE=1, startup 완료=1, CRC/ID 오류=0을 확인했습니다. **Python wrapper를 통한 실제 업로드도 성공했습니다.** [Python 실행 결과](../artifacts/dmd-program-20261027/python/result.json)와 [원본 로그](../artifacts/dmd-program-20261027/python/program.log)를 별도로 보관했습니다.

```powershell
python tools/ise_program.py --program --bitstream "artifacts/dmd-20261026/appsfpga_repaired_jtag.bit"
```

PC의 USB에 연결하는 **Xilinx JTAG 다운로드 케이블**과 보드의 **D4100 패턴 전송 USB**는 별도입니다. JTAG 구성에는 전자가 필요하고, `dmd-test status/upload/show`에는 후자가 필요합니다. Python 도구도 이 구분을 따르며 D4100 USB를 VM에 연결하지 않습니다.

앞선 실패에서 연결이 복구된 원인은 확정되지 않았습니다. 직접 iMPACT 구성 후, Python 재구성 전 D4100 USB 조회는 `Devices=0, Connected=false`였습니다. 사용자는 패턴 USB 분리가 영향을 주었을 가능성을 제시했지만, 연결/분리 조건을 통제한 비교를 하지 않았으므로 **패턴 USB 분리를 JTAG 성공의 필수 조건으로 단정하지 않습니다.**

## 남은 실기 검증

이 수정 bitstream에서 D201 응답, DDR2 calibration, 패턴 업로드 및 광학 출력을 아직 확인하지 않았습니다. 보드 전원을 유지한 상태에서 패턴 USB를 Windows에 연결하고 SW2를 눌렀다 놓은 뒤, `DMD-FPGA-Test`에서 다음 순서로 확인합니다.

```powershell
dmd-test status
# Devices=1, FPGA_ABI=0xD201, Calibrated=true를 확인한 뒤
dmd-test upload
dmd-test show --number 1
```

단일 이미지의 숫자와 L 마커가 올바른지 확인한 다음 시퀀스 검증을 진행합니다. 이번 구성 성공은 앞서 관찰된 영상 깨짐이 해결됐다는 광학 검증 결과가 아닙니다. JTAG 구성은 휘발성이므로 보드 전원을 껐다 켰다면 재구성이 필요합니다.
